# 群聊「今日值得关注」摘要

> ⚠️ **样板状态**：本文件按 `docs/SPEC.md` v0.2 填写，用于验证 `pattern-only` 契约可写。
> 结构与做法已确认；标 `<!-- TODO -->` 的实现细节需作者核实。

## 目标

每天把你所在的全部工作群扫一遍，产出一份**「今天值得关注、但你还没看」**的摘要。

产出是一份分级清单：**需要你回应的** / **需要你知道的** / **可以忽略的**（只给条数，不展开）。

这是 `pattern-only` 类型——**产出永远不公开**，公开的只有做法。你的 Agent 在你自己的群、你自己的数据上跑。

## 需要你提供

| 名称 | 敏感 | 用途 | 拿不到时 |
|---|---|---|---|
| `IM_APP_ID` | 是 | 读取群消息的应用凭证 | 无法运行，必需 |
| `IM_APP_SECRET` | 是 | 同上 | 无法运行，必需 |
| `WATCHED_CHAT_IDS` | 否 | 要扫的群列表；留空则扫全部可见群 | 扫全部，噪音会更大 |
| `SELF_USER_ID` | 否 | 用于判断「@我」和「我已回复」 | 降级：无法识别待回应项 |
| `DIGEST_TARGET` | 否 | 摘要投递到哪（私聊/文档/本地文件） | 默认写本地文件 |

🔴 敏感项存进你自己的密钥管理，**不要贴在对话里**。这份定义里从来没有任何值。

## 信源

你自己的即时通讯群聊。**不抓任何外部信源。**

**取数范围**：上一次运行时间 → 本次运行时间之间的全部消息。首次运行取过去 24 小时。

**去噪规则**（🔴 这是本 loop 最值钱的部分）：

1. **丢弃纯社交噪音**——收到/好的/表情回复/接龙/日常寒暄
2. **丢弃机器人播报**——除非其中含异常或告警关键词
3. **丢弃你已经回复过的话题**——判据：该话题最后一条消息晚于你在该话题的最后发言
4. **合并同一话题的连续消息**——按时间窗 + 参与人聚类，不要逐条列

**分级判据**：

- **需要你回应**：@你、向你提问、等你决策、指派给你的事项
- **需要你知道**：与你负责的项目/人相关的结论、变更、风险，但不需要你动作
- **可忽略**：其余，只报条数

## 触发

- 周期：每日一次
- 时点：`0 20 * * *`（下班前，还来得及处理当天的事）
- 时区：`Asia/Shanghai`
- 错过补跑：**是**。按「上次运行时间」推进取数游标，不会漏，但要防止一次取太多。

## 产出格式与投递

```
📋 今日值得关注 · <日期>

🔴 需要你回应（N 条）
- [群名] <一句话话题> — <谁在等你> — <链接>

🟡 需要你知道（N 条）
- [群名] <一句话结论或变更> — <链接>

⚪️ 已忽略 N 条社交噪音 / M 条机器人播报
```

**投递**：按 `DIGEST_TARGET`，默认写本地文件。

🔴 **产出永不写入 Hub**——这是 `pattern-only` 的定义。`visibility.outputs: private`，且本目录不得包含 `runs/`。

**失败处理**：取数失败保留上次游标不推进，下次补齐；连续 2 次失败告警。

## 验收标准

- [ ] 「需要你回应」一栏**零漏报**——所有 @你 且你未回复的，必须出现
- [ ] 「需要你回应」一栏 ≤ 10 条；超过说明分级判据太松，需收紧
- [ ] 每条都能点回原消息（带链接）
- [ ] 无实质内容的当天，明确产出「今天没有需要你回应的」，**不硬凑**
- [ ] 🔴 产出中不含任何群成员的手机号、邮箱、身份证等 PII
- [ ] 失败信号：连续 3 天「需要你回应」为空但群里确有 @你 → 分级判据或 `SELF_USER_ID` 有问题
